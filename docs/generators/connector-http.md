# Connector HTTP

Генератор Connector формирует код для библиотеки
[Connector](https://github.com/vbondarevsky/1connector). Используйте её, если проект уже работает через
`КоннекторHTTP` и типы ответа Connector.

## Выбор генератора

```shell
curlone convert --target connector "curl https://example.com"
```

В библиотечном API:

```bsl
Параметры.Цель = ЦелиКонвертацииCURL.КоннекторHTTP();
```

Идентификатор генератора: `connector`. Поддерживаемые локали: `ru` и `en`.

## Параметры

| Настройка | Тип | Значение по умолчанию | Назначение |
| --- | --- | --- | --- |
| `ФорматДесериализацииОтвета` | строка | `Неопределено` | Формат обработки тела HTTP-ответа |

Значение `ФорматыДесериализацииОтветаCURL.JSON()` выбирает методы Connector с суффиксом `Json`. Для HTTP API этой
настройке соответствует `generatorOptions.responseDeserializationFormat`.

## Поддерживаемые сценарии

Генератор формирует HTTP- и HTTPS-запросы, включая методы, заголовки, данные формы и JSON, загрузку файлов,
составные формы, аутентификацию, HTTP-прокси, сертификаты и запись результата в файл.

Digest поддерживается средствами Connector. NTLM и Negotiate используют аутентификацию операционной системы,
в том числе без явно указанного пользователя.

## Ограничения

- FTP и FTPS не поддерживаются и останавливают генерацию.
- Режим получения только имён, удаление заголовков, перенаправления, повторы и таймауты могут отличаться от curl.
- Повторяющиеся заголовки и источники заголовков могут приводить к потере части данных.
- SOCKS-прокси и AWS Signature v4 формируются приближённо.

Представимая потеря даёт предупреждение. Неподдерживаемая обязательная семантика возвращает ошибку
`curlone.generator.unrepresentable_semantics`.

Полный перечень приведён в [матрице возможностей](../МатрицаВозможностейCURL.md).
