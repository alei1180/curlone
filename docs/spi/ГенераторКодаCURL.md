# SPI генератора кода CURL

`ГенераторКодаCURL` — duck-typed контракт для подключения сторонних генераторов к curlone. Генератор не
наследует общий базовый класс: совместимость определяется наличием методов с точными сигнатурами и значениями,
описанными ниже.

Текущая версия контракта — `1`. Реестр принимает генератор, только если `ВерсияКонтракта()` точно равна
`ВерсииКонтрактаГенератораCURL.Актуальная()`. Проверка и регистрация появятся в Plan 5.

## Обязательные методы

```bsl
Функция Идентификатор() Экспорт
Функция Наименование() Экспорт
Функция ВерсияКонтракта() Экспорт
Функция Возможности() Экспорт
Функция Сгенерировать(КонтекстГенерацииКода) Экспорт
```

- `Идентификатор()` возвращает уникальную непустую строку. Это стабильный машинный идентификатор генератора.
- `Наименование()` возвращает непустую строку для отображения пользователю.
- `ВерсияКонтракта()` возвращает число — поддерживаемую версию SPI. Для версии 1 допускается только точное
  совпадение с актуальной версией.
- `Возможности()` возвращает `ФиксированныйМассив` строковых идентификаторов возможностей. Массив и содержащиеся
  в нём значения рассматриваются как неизменяемые.
- `Сгенерировать(КонтекстГенерацииКода)` принимает только публичный `КонтекстГенерацииКода` и возвращает строку
  программного кода BSL.

## Границы ответственности

Генератор получает уже разобранное и нормализованное представление операций. Он не разбирает исходную curl-команду,
не получает DTO библиотечного, CLI- или HTTP-адаптера и не изменяет переданный контекст.

Ожидаемые ограничения представления оформляются как `ПредупреждениеКонвертацииCURL` до вызова генератора. Нарушение
формы SPI при регистрации или вызове оформляется ошибкой `КодыОшибокCurlOne.НарушенКонтрактГенератора()`,
а несовпадение версии — `КодыОшибокCurlOne.НесовместимаяВерсияКонтрактаГенератора()`. Runtime-проверки этих правил
относятся к Plan 5.

Исполнимый минимальный пример находится в `tests/spi/Классы/СтороннийГенераторДляТестов.os`; контрактный тест
использует только публичные типы curlone.
