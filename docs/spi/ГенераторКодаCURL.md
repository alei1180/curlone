# Контракт генератора CURL

Собственный генератор позволяет добавить новую цель без изменения ядра curlone. Наследование не требуется: реестр
проверяет наличие пяти экспортных функций и их сигнатуры.

Актуальная версия SPI: `ВерсииКонтрактаГенератораCURL.Актуальная()`, сейчас это число `1`.

## Обязательные функции

| Функция | Параметры | Результат |
| --- | ---: | --- |
| `Идентификатор()` | 0 | Непустая строка без внешних пробелов |
| `Наименование()` | 0 | Непустая строка для отображения |
| `ВерсияКонтракта()` | 0 | Числовая версия SPI |
| `Возможности()` | 0 | `ФиксированныйМассив` уникальных кодов |
| `Сгенерировать(Контекст)` | 1 | Непустая строка программного кода |

Регистр имён функций не влияет на проверку. Идентификаторы целей регистрозависимы.

## Минимальный генератор

```bsl
Функция Идентификатор() Экспорт
    Возврат "example";
КонецФункции

Функция Наименование() Экспорт
    Возврат "Пример генератора";
КонецФункции

Функция ВерсияКонтракта() Экспорт
    Возврат ВерсииКонтрактаГенератораCURL.Актуальная();
КонецФункции

Функция Возможности() Экспорт
    Коды = КодыВозможностейГенератораCURL;
    Результат = Новый Массив;
    Результат.Добавить(Коды.ПротоколHTTP());

    Возврат Новый ФиксированныйМассив(Результат);
КонецФункции

Функция Сгенерировать(Контекст) Экспорт
    Операции = Контекст.Операции();

    Возврат "// Сформированный код";
КонецФункции
```

Полный рабочий пример находится в
[`СтороннийГенераторДляТестов.os`](../../tests/spi/Классы/СтороннийГенераторДляТестов.os).

## Регистрация

```bsl
Реестр = Новый РеестрГенераторовCURL;
Реестр.Зарегистрировать(Новый МойГенераторCURL);

Конвертер = Новый КонвертерCURL(Реестр);
```

Переданный реестр заменяет встроенный. Если нужны цели `1c` и `connector`, зарегистрируйте их явно вместе со своим
генератором.

Реестр один раз читает метаданные и сохраняет их снимок. `Сгенерировать()` при регистрации не вызывается.

## Контекст

`Сгенерировать()` получает [`КонтекстГенерацииКода`](КонтекстГенерацииКода.md), содержащий:

- нормализованные операции;
- код локали;
- параметры генератора;
- идентификатор выбранной цели;
- снимок объявленных возможностей.

Генератор не должен повторно разбирать исходную команду. Для проверки возможностей используйте
`Контекст.ВозможностиГенератора()`, а не повторный вызов собственной функции `Возможности()`.

Модели операций передаются для чтения. Параметры генератора передаются по ссылке и могут содержать изменяемые
объекты, поэтому договор об их изменении определяет сам генератор.

## Возможности и потери

До генерации ядро сопоставляет команду с [каталогом возможностей](ВозможностиГенераторовCURL.md).

- отсутствие обязательной возможности останавливает генерацию;
- для представимого приближения создаётся предупреждение;
- неактивные настройки сохраняются в модели, но не должны вычисляться сформированным кодом;
- литеральное и вычисленное значение должны обрабатываться одинаково после определения фактической ветви.

## Ошибки

| Ситуация | Код |
| --- | --- |
| Неверная форма функции или метаданных | `curlone.generator.contract_violated` |
| Неподдерживаемая версия SPI | `curlone.generator.incompatible_contract` |
| Исключение при генерации | `curlone.generator.failed` |
| Пустая строка или значение неверного типа | `curlone.generator.contract_violated` |

Исключение генератора сохраняется как причина структурированной ошибки. Безопасная пользовательская диагностика не
раскрывает исходную команду и внутреннее описание исключения.

## Параллельные вызовы

Один объект генератора может одновременно обслуживать несколько преобразований. Храните данные вызова в локальных
переменных. Общее изменяемое состояние защищайте с помощью `БлокировкаРесурса`.

Сервис не создаёт копию параметров генератора и не синхронизирует доступ к ним. Если вызывающая сторона передаёт
одни и те же изменяемые объекты в несколько вызовов, согласование доступа остаётся на ней и на генераторе.
