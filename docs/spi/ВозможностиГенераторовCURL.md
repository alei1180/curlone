# Возможности генераторов CURL

Генератор объявляет фиксированный массив возможностей при регистрации. Реестр проверяет идентификаторы
по закрытому каталогу версии 1 и сохраняет снимок. При генерации следует использовать
`Контекст.ВозможностиГенератора()`: повторно прочитанные метаданные объекта не меняют договорённость с ядром.

## Именованные коды и группы

Модуль `КодыВозможностейГенератораCURL` предоставляет функции перечисления.
Они возвращают стабильные строки из таблицы ниже и доступны при подключении библиотеки.

`КодыВозможностейГенератораCURL.Все()` возвращает общий `ФиксированныйМассив` всех 61 объявляемой
возможности в нормативном порядке. Массив создаётся при инициализации модуля и возвращается без копирования.
`КодыВозможностейГенератораCURL.Содержит(Код)` проверяет принадлежность этому набору.
Поиск использует общее фиксированное соответствие «код → позиция», а `Все()` возвращает массив
в нормативном порядке. Оба контейнера создаются один раз при инициализации модуля.
Служебный `protocol.dynamic` в него не входит. Отдельный класс каталога не используется.

```bsl
Коды = КодыВозможностейГенератораCURL;
Возможности = Новый Массив;
Возможности.Добавить(Коды.ПротоколHTTPS());
Возможности.Добавить(Коды.НесколькоОпераций());
Возможности.Добавить(Коды.ВыраженияЗначений());

ЭтоПротокол = Коды.ЭтоПротокол(Коды.ПротоколHTTPS()); // Истина
ЭтоВыражение = Коды.ЭтоВычисляемоеЗначение(Коды.ВыраженияЗначений()); // Истина
ЭтоЗаголовок = Коды.ВходитВГруппу(Коды.ПорядокЗаголовков(), "headers"); // Истина
```

`ВходитВГруппу(Код, Группа)` учитывает регистр и границу по точке: `protocol.http` входит в `protocol`,
а `protocols.http` не входит. Проверка поддерживает вложенные группы и требует непустой суффикс.
Совпадение кода с именем группы, пустая группа и группа с конечной точкой дают `Ложь`.
Функция проверяет структуру имени, а допустимость объявления проверяет реестр по каталогу версии 1.
Неверный тип аргумента вызывает `argument.invalid_type`.

`ВычисляемыйПротокол()` и функции `Для...` относятся к служебному интерфейсу ядра.
Код `protocol.dynamic` обозначает требование вычисляемого протокола и отсутствует в каталоге:
генератор объявляет конкретные поддерживаемые протоколы.

## Активность настроек

Требования выводятся из итоговой модели. Отменённые опции не создают требования. Повторы активны при положительном
или динамическом количестве; их ограничение времени учитывается только при активных повторах и положительном
или динамическом времени. Отключённый прокси исключает свои учётные данные и способы аутентификации.
Каталог результата и создание каталогов учитываются при файловом, удалённом или отложенном режиме результата.
Режим FTP и адрес обратного соединения учитываются только для FTP/FTPS или возможного динамического протокола.

Неактивный подграф сохраняется в контексте, но не должен вычисляться целевым кодом. При динамическом управляющем
значении сначала вычисляется оно, затем определяются необходимые зависимые значения. Например, при вычисленном
нуле повторов ошибочное значение переменной ограничения времени не вычисляется.

## Ошибки и предупреждения

Отсутствие обязательного протокола, `operations.multiple`, `values.expressions` или
`values.deferred_classification` создаёт `curlone.generator.unrepresentable_semantics` и останавливает генерацию.
Для динамического протокола заранее нужна хотя бы одна `protocol.*`; конкретное значение проверяет целевой код.

Остальные отсутствующие возможности дают `curlone.generator.unsupported_capability`. Генератор обязан
документировать приближение: пропуск неподдержанной части или настройку, которую он способен сохранить.
При пропуске файлового источника файл не читается и фиктивные данные не создаются. Для оставшихся частей тела
сохраняются порядок и правила соединения, включая отсутствие разделителя перед первой оставшейся частью.

Анализатор собирает независимые предупреждения даже при наличии блокирующей ошибки. Порядок определяется
операциями, затем каталогом. В пределах операции одинаковое требование объединяется с первым его источником.
Диагностика содержит идентификаторы возможности и цели, каноническое имя опции и позицию исходного токена.
Значения команды, пути и содержимое источников в сообщения не включаются.

## Выражения и внешние источники

Для отложенной классификации учитываются все достижимые варианты с учётом литеральных ограничений.
Для конечных маркеров `-`, `.`, `@-` и пустой строки учитываются все литеральные фрагменты, включая суффикс.
Например, `--upload-file "$PATH.txt"` не допускает стандартный ввод, а `--user-agent "$AGENT/client"`
не допускает удаление заголовка. Переменная может быть пустой; повторные переменные оцениваются консервативно.
Известная схема `https://` исключает зависимые FTP-настройки даже при переменных в остальном URL.
Полностью известная часть адреса до пути без учётных данных исключает `auth.credentials`,
а переменная внутри этой части сохраняет такую возможность.
Например, `--data "$BODY"` допускает файловый источник и стандартный ввод, а `--data-raw "$BODY"` сохраняет текст.
При отсутствии нужной возможности предупреждение заранее сообщает о возможной потере после вычисления значения.
Целевой код применяет объявленное приближение только к фактически выбранной ветви, одинаково для литерала
и результата вычисления выражения.

Источник заголовков из файла или стандартного ввода дополнительно требует потенциальные `headers.ordered`,
`headers.repeated`, `headers.empty` и `headers.remove`. Это относится и к заголовкам отдельной части формы.
Поддержка `headers.file` не подразумевает поддержку всех операций над прочитанными заголовками.
Предупреждения о возможных потерях возвращаются до чтения даже при литеральном имени файла.
Ядро не читает источники и не запрашивает значения переменных. Сам внешний источник не требует возможностей
динамических выражений, если его имя и способ обработки уже известны.
